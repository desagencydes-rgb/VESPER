## 1. READ THIS BEFORE TOUCHING ANYTHING

Four traps. Each one has already cost this project real time, and each one
looks like an improvement from the outside.

**Do not "fix" the ad-hoc code signing.** `build.sh` signs with `--sign -`, and
the obvious fix is the certificate already sitting in the keychain ("VESPER
Local Signing", valid to 2036). It was measured: a self-signed certificate
gives stable TCC identity AND makes launchd refuse to spawn the login item
(`OS_REASON_CODESIGNING`), so VESPER never starts after a reboot. The note is
above `codesign` in `build.sh`. Only a Developer ID certificate buys both.

**Every build destroys the owner's TCC grants.** Ad-hoc signatures are keyed to
a content hash, so each build is a new app to macOS. This is why the work order
below exists: the goal is exactly ONE more build, so the owner makes exactly
one trip through System Settings. Do not build early to "test something".

**`self_test.py` mutates the live repo and must run ALONE** (~55 min). Two
overlapping runs produce false failures. It cannot run while anything is being
edited, which is why it is late in the order and not first.

**`python3.13`, never `python3`.** System python is 3.9, every gate dies on
`tomllib`, and `checks.py` still exits 0 while doing it. A session that trusts
the exit code records a pass it never had.

## 3. WHAT LANDED THIS SESSION

**The replay storm.** `_present_enable_token` re-presented the same token every
tick; the interlock correctly refused each one and published an event. 343,470
records — over 80% of everything VESPER had ever logged — plus 610,931 in a
636 MB rotated segment. Its docstring said "if it is new" and the code had no
such test. Fixed by asking the interlock what it already holds. Verified live:
0 refusals in 45 minutes, against ~3.9/second before. Gated by `CI-119`.

**`build.sh` agent registration.** Was two fixed passes with `sleep 6`, before
the LaunchAgent reload. Measured: both passes ran, the build printed success,
and `.wake` and `.fnwatch` were both at `EX_CONFIG` when it finished — the
globe key and the microphone dead while the build said it had fixed them. Now
runs after the reload, retries up to six times, and asks launchd for a PID
rather than counting passes. The first version of that predicate looped over an
unquoted string, which bash splits and zsh does not; it reported "NOT UP" for
three agents, two of which had live PIDs. Now tested in bash, sh and zsh.

**The yes-loop.** The owner said "yes" three times and got the same question
back three times. Three stacked faults:

- the runtime never passed `attention_state`, so it defaulted to UNKNOWN, so
  `budget_for` returned `DEFAULT_BUDGET = 0`, so every confirmation QUEUED
  instead of being asked, so `asked` was False — and `Actor.answerable()`
  requires `asked` before a bare yes may settle anything, deliberately, so no
  yes could ever resolve anything;
- `maybe_act`'s default `period="active"` is not a member of
  `interruption.PERIODS`, so the lookup missed and fell to the same 0 even with
  attention known. A `dict.get` returning the fail-closed default for a TYPO is
  indistinguishable from the same default as policy;
- `_ask_sentence` said "Say yes and I will" for a question that had only been
  queued.

Presence is now MEASURED — an owner utterance dispatched in this iteration,
with `PRESENCE_FRESH_S = 20` decaying back to UNKNOWN — not defaulted to
"available", which is the declared-vs-measured error `confirm.py` warns about
in its own docstring. Verified: `ACTIVE_SESSION` + `available` -> budget 6,
`asked=True`, answerable 0 -> 1.

**Permission modes.** `core/permission_mode.py`. Three modes:

| mode | standing grant | means |
|---|---|---|
| `ask` | L2 | today's behaviour, asks above read-and-workspace |
| `workspace` | L5, ceiling drops outside | free in its own folder, asks beyond it |
| `auto` | L5 | no questions |

    python3.13 tools/ops/vesper_runtime.py --permission-mode auto
    python3.13 tools/ops/vesper_runtime.py --permission-mode-status

Implemented as a new `mode_ceiling` parameter on
`PolicyDecisionPoint.authorize` that only ever LOWERS, kept separate from
`context_ceiling` on purpose: that one is INV-ACT-3 refusing to let content
raise authority, and merging them would let whichever caller passed last widen
it. **No mode touches `context_ceiling`** — auto mode is the owner trusting
VESPER, not the owner trusting everything VESPER reads. Workspace mode is safe
for `shell.run` without path analysis because the seatbelt profile already
confines writes to the workspace and denies the network at the kernel.
Verified: 3 modes x 4 cases through the real ladder, `ask` unchanged.

**The agenda — the loop's other half.** `core/agenda.py` reads a plan file
VESPER can also WRITE plus an EventKit dump, ranks by importance x urgency
(multiplied, not added, so importance scales urgency and cannot manufacture
it), and keeps "nothing is due" strictly apart from "a source is unreadable"
(INV-HW-2). `app/island-macos/AgendaBridge.swift` reads Calendar and Reminders
through EventKit — NOT the raw stores, which need Full Disk Access and would
hand VESPER mail, messages and browser history to read appointments. Sensor
`agenda-due` and trigger `trg_agenda_item_due` registered, anti-cron gate
passes.

**The loop speaks.** The trigger originally shipped with no handler and no
intent, so it fired, dispatched, hit `if not intent: continue`, and did
nothing — the sensing half with no acting half. The owner chose SPEAK over
notify. The handler renders `agenda.sentence()` first, offers the model the
chance to phrase it better, speaks it, and appends it to the transcript. The
model phrases and never decides (INV-AUTO-2); a model failure degrades to the
deterministic line and is never a silence. Measured through real dispatch:
without handler `fired=1 dispatched=0 spoke=0`; with it, `spoke=1`.
`dispatch()`'s return value was also being discarded, so anything autonomy said
would have been audible and invisible.
