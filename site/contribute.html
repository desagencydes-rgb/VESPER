Contributor field guide

Pick up a piece.

The original author has stepped back. Choose one change, say how you will prove it, and open an issue so someone else can build alongside you.

Runtime

Give spoken questions a quicker answer.

A recorded turn took about 30 seconds on 8 November 2026. Someone waiting that long cannot tell whether VESPER heard them.

Where to start

Start with the fixed capture window. End recording on silence, then compare wake-to-answer timings on the same question. The open-work ledger also names quota, missing grants and startup probes.

Open an issue ↗WakeWord.swift ↗
Desktop surfaces

Give Windows and Linux a home.

The core and gates already run on both platforms. People there need a visual shell to see the work unfold.

Where to start

Begin with the showcase’s scene format. Build one pane in a Tauri window, feed it a real scene and verify the rendered result. The island has its own native requirements.

Open an issue ↗Showcase layout ↗
Speech

Keep the runtime listening while it speaks.

A synchronous call leaves the pump deaf for an entire sentence. The queue, worker and interruption path already exist.

Where to start

Connect core.speech.Voice at both blocking runtime call sites. Prove the pump can work during a long line and that interrupt stops speech and clears the queue.

Open an issue ↗Speech worker ↗
Showcase

Let VESPER compose the scene.

The showcase can draw and annotate a scene, but each demonstration so far was written by hand.

Where to start

Trace a checked scene through the end-to-end harness. With model access configured, let a situation choose the panes and words, then inspect the window it actually drew.

Open an issue ↗Showcase harness ↗
Verification

Make a pending check enforce its rule.

On 9 November 2026, 18 of 207 registered checks were still marked PENDING. An executed red run shows the check can catch the fault.

Where to start

Choose one PENDING row. Implement it, add its sabotage case to tools/ci/self_test.py and observe red, then green. Run the self-test alone and let it restore the tree before committing.

Open an issue ↗Check registry ↗

Before your first change

Read the open-work record and its measurements. Keep tools and verification in the Python standard library. A successful launch is only the start of a test. Look at the window, listen to the sentence, or read the state back.
