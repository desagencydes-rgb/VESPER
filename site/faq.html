Frequently asked questions

A few answers.

Identity, privacy, platforms and the decision to open the work.

What is VESPER?

A persistent, distributed artificial operating presence. Models provide judgement, while identity, memory, policy and continuity belong to VESPER. It can sense and act on a real machine within its authority limits.

What can I run today?

Apple Silicon Macs running macOS 13 or newer have the native island, home, showcase and summon controls. Intel Macs, Windows and Linux can run the Python core and gates. The visual shell for Windows and Linux still needs contributors.

Where do my keys live?

Your credentials belong in ~/.config/vesper/secrets.env, outside the repository, readable only by your user. The credential checker reports shapes and lengths. Give VESPER its own subscription account and configuration directory.

Does everything stay on my machine?

Model routing can send content to a provider. Egress class is checked before quota. E2-PUBLIC rungs may receive only public content. Private content requires a provider eligible for E1-PRIVATE and any required privacy setting. Speech recognition for en-US is on-device. Other locales may send audio to Apple.

Can it work without a provider?

The surfaces can draw and listen with no model credential. To think and talk through a model, VESPER needs at least one configured and available rung.

Can VESPER take over my Desktop?

It only takes an empty Desktop on its own. Pressing the globe key three times explicitly calls it to the Desktop you are using. Screen access and driving windows also require macOS grants.

Why open source now?

One person built the foundation and stepped back, leaving the code under MIT and publishing the open-work record. It names the broken behavior, unfinished mechanisms and unanswered questions so another person can take over one piece.

How can I help without building the whole app?

Reproduce an install failure, exercise a pending check, or measure one part of a spoken turn. The contribution guide links each task to a starting file and a ready-to-edit issue.
