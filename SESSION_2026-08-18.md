### Three things bought that were not on any list

1. **The `arm` subcommand is Windows-only.** It shells out to PowerShell on the
   node that has no PowerShell, so the machine the alarm lives on has no wake
   path at all. Found by taking the owner's "what if the laptop sleeps?"
   seriously instead of answering from the design's own claim.
2. **The watchdog's first version passed all three refusals and still did not
   work.** `KillMode=control-group` killed the restored alarm 2 ms after launch,
   while the journal logged `relaunched_pid` and `Result=success`.
3. **`Linger=yes` is set; autologin is deliberately not.** It would remove the
   laptop's login password, and a sudo password handed over to fix a reboot
   hole is not consent to make that trade.

### Open, and needing the owner

- **Do not power off or suspend node 2.** The reboot path is expected to work
  and is **not verified**; the only thing that verifies it is an attended reboot.
- **Mask the sleep targets?** One reversible command removes the suspend
  failure mode entirely. It takes away a capability, which is why it is asked
  rather than done.
- **20 commits sit on `feat/f0-f1-endurance` with no PR.** The "wait for the
  ultra review" premise is dead, so nothing gates one.
