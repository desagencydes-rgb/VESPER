What VESPER's home could look like.

Every surface below is rendered live from the decided system — the ten palette colours, the four glass tiers at their real blur and fill values, the four springs sampled off this machine, and the eleven ambience modes taken from the light source in each of the owner's images.

The geometry is measured. The composition is a guess, and I would rather be corrected than agreed with.

These are proposals, not references

docs/design/ui-refs/ covers the island only. The composition of the home — where a card sits, how big a widget is, what the main menu holds — is undecided and has never had a reference set. What is decided and honoured here: the palette, the glass tiers, the type, the springs, the eleven ambience modes, the island's measured geometry, and every behavioural rule in the architecture. What is invented here: the layout. Mark it up and it becomes the reference set the home has been waiting for.

01 — the desktop environment

A Desktop, not a fullscreen window

macOS has no public API to create a Space, so VESPER's home is a ground window at level normal − 1 on a Desktop you make once in Mission Control. Three things follow, and your reference confirms all three: the menu bar stays and is tinted by the ground, there is no black band across the top, and the island is not drawn here at all — it exists because VESPER is not on screen, and in the home it is.

The ground is your own wallpaper for that mode. Each mode's accent was derived from the light source in this very picture, so the interface and the photograph behind it are the same colour by construction rather than by taste — measured, all eight modes within 30°, none diverging.

02 — the z-order law

Ground never rises, float never sinks

A card that can end up behind an app window is a card you will lose. An app window that can end up behind the ground is work you will think VESPER closed. One integer prevents the first failure: a window below the normal level cannot rise above a normal window even when it is clicked.

04 — the presence law

The face's claim is inverse to the work's

The stage owns the tier, and a behaviour may never raise its own — the same shape as the rule that says a behaviour chooses where to look and how urgently but may not change the envelope. Dispersed is a release, not a fade: the same point cloud with the head's attractor turned off, drifting to a low-energy field. It is the second addition to the motion vocabulary, after the mark's four state motions.

Centre

The head, eight panel anchors, the full behaviour set. Home, Rest, conversation, wake.

Attendant

A corner anchor, same envelope, reduced amplitude. Work you do with VESPER.

The attractor released. The points become the field the widgets sit in. Research, study, analysis.

Absent

These previews run ~900 points in a canvas; the native renderer runs 39,805 in Metal at a measured 5–7% CPU. Whether the dispersed tier actually costs less than the centred one is unmeasured, which is why it is pre-registered as a pass condition rather than assumed.

05 — ambience

Eleven modes, eleven light sources

Grounds are the darkest cluster in each of the owner's images; accents come from the light source — the top 4% of pixels by brightness × chroma — because the mean of a night photograph is just the night. Eight measured, three curated with the reason recorded. Pick one and the whole screen above cross-fades on --smooth.

Mode and stage are different axes. Ambience follows what VESPER is doing; the stage follows what you are doing. A stage never changes because VESPER started thinking, and ambience never changes because you opened a paper — conflating them produces an interface that rearranges itself while you read.

06 — what happens next

Fifty-six of ninety need no backend

The catalogue's own status field put twenty-six cards within reach before a producer runs. Reading the modules instead of the field found fifty-six — eleven "suggestions" turn out to be walks over structures that already exist. Everything on this page is in the first phase.

The rule that makes phase F safe: a fixture must be visibly a fixture. The whole culture of "a number is measured or it is unknown" leaks the moment a demo value renders in the same style as a measured one — so fixtures do not enter the projection at all. A Reading cannot hold a value without provenance, which makes the dishonest version unconstructible rather than merely discouraged.

The two stages to build first are Research — your flagship, and both halves are frontend — and Improving itself, the only stage where every card it holds is already true today.
