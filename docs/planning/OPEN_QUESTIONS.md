# Open questions, deferred claims, and known blind spots

**This file is a register, not a plan.** Nothing here blocks building. Every
entry is something that cannot be answered yet, or a claim that was asserted
and never checked. Entries are added whenever one appears; they are removed
only when answered, with the answer written in.

**Why it exists.** The failure this guards against is not being wrong. It is
being wrong and having no record that the question was ever open — an
assumption that hardens into a fact because it was stated confidently in a
document that nobody re-read.

Three kinds of entry:

- **UNVERIFIED CLAIM** — asserted in a design document, never measured. The
  most dangerous category, because it reads exactly like a finding.
- **BLOCKED QUESTION** — cannot be answered until something is built.
- **KNOWN BLIND SPOT** — cannot be answered at all by the instruments planned.
  These do not become answerable later; they need a different instrument, or
  they stay open forever and the design must survive them being wrong.

## Known blind spots — no planned instrument can see these

**These do not resolve with time.** Recording them so that a later conclusion
is not read as stronger than the instrument that produced it.

| # | Blind spot | Why nothing planned catches it |
|---|---|---|
| K1 | **The confident wrong answer nobody notices.** Misses are caught by the owner repeating something, correcting something, or VESPER saying "I don't have that." A wrong answer accepted as right leaves no trace of any kind | Every detector is triggered by the owner reacting. Silent acceptance produces no event |
| K2 | **The capture instrument shapes the corpus it produces.** If automatic capture is selective in some way, every later measurement inherits that bias and reads as a property of memory rather than of the recorder | The corpus is the only evidence, and it is generated by the thing being judged |
| K3 | **n = 1 person.** Everything measured describes one owner, one working style, one vocabulary | There is no second user, and there should not be |
| K4 | **Weeks, not years.** Memory behaviour over months of accumulation cannot be observed by running for weeks | Only time fixes this |
| K5 | **A miss and a refusal look identical from outside.** VESPER declining to answer and VESPER being unable to are the same event in the log unless deliberately distinguished at the moment it happens | Needs the distinction recorded at write time, not reconstructed later |
| K6 | **Provider behaviour changes underneath us.** Caching, rate limits and latency are vendor policy and can change with no announcement | Any measurement has a shelf life; none of them are permanent facts |

**K1 is the important one.** It is the same shape as the problem the whole
memory design exists to solve — an absence nobody observes — and it applies to
the instrument built to detect absences. The mitigation is not a better
detector. It is periodically asking the owner to check a sample of answers
against the record, which is expensive and which nobody will keep doing.

## Problems observed and not explained

| # | Observation | Status |
|---|---|---|
| P5 | **The cache discount does not reproduce.** 1 hit in 14 on Mistral, 0 in 4 on Groq. One 99.6% observation against 17 misses | Premise withdrawn. The design survives on a cost argument needing no cache |
| P6 | **A probe with no positive control nearly produced a false finding.** The truncation test read "truncation misses" where the cache had simply never populated — byte-identical outputs | Fixed: positive control must hit and negative control must miss before the result is read at all |
| P7 | **A patch script asserted on a hyphen where the file holds an en-dash, aborted, and `git commit` ran anyway** as a separate command — twice. A commit message described findings that were never written | Verify the write landed before committing; never chain a patch to a commit with `&&` |
| P8 | **`git add -A core/` committed the history plumbing under an unrelated message**, landing `gateway.py` without its `routing/supply.py` half | Repaired in 58d51eb. Stage explicit paths, never a directory |


| # | Observation | Status |
