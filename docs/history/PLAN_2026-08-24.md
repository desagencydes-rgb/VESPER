## 0. Before anything else — I was about to do the wrong thing first

Asked "frontend or the core engine", I answered **the core**, and specifically:
wire a real provider behind the gateway, because `core/gateway.py` is the only
file in the repo that defines a `Provider`, it holds `call: Callable[[str, dict],
dict]`, and F1's acceptance registers three fakes — so the cost choke point, the
router, the planner and the verifier are all green against test doubles and
**VESPER has never made a real model call.**

That part is true. The ordering was wrong, and the owner asked the question that
found it: *"check if it's the one that should be done, or if there is actually a
baseline or ground more important to start with, to not end up with a mess
later."*

There is. `core/enrollment.py`, `A-042.4`:

> `sustained_tokens_per_sec` **IS MEASURED AT ENROLLMENT, NEVER DECLARED**
> (`INV-HW-2`), and **a node with no measured profile is NEVER ROUTED TO.**
> Fail-closed: the alternative sends real work to a node on the strength of a
> datasheet.

`router.py`'s `MeasuredProfile.usable` returns `measured and wall_tokens_per_sec
is not None`. `capability_profiles.toml` carries `unmeasured_disposition =
"UNAVAILABLE"` and every `sustained_tokens_per_sec_min` reads `UNKNOWN`. And
`contracts/entities/node_capability_profile.schema.json` — written 2026-08-20 —
**has never been instantiated. There is not one enrolled node profile on disk.**

So a provider wired today is a provider the router will never route to. It would
only work registered **directly** with the gateway, bypassing enrolment,
placement and the fabric — a second path to the model, which is exactly the path
the whole design exists to prevent. That is the mess, and it would be load-
bearing by the time anyone noticed.

**The ground is enrolment. The provider is the step after it.**

## 3. Track B — the machine, no owner needed until A1

### B1 · The node profile instance *(before A1, feeds it)*

Build the first `node_capability_profile` instance from the `SPIKE-001` §3.1
results: tier, node class, `wall_tokens_per_sec`, the context slope where it was
measured, and the provenance — **including the build tag.** `MEMORY.md` §1 is
explicit that node 1 has two `llama-server.exe` and only build `b10405` is
comparable; a figure without its build tag is not a measurement.

Validate against `contracts/entities/node_capability_profile.schema.json`.
Produce the diff. **Stop there** — the write is `A1`.

### B2 · The enrolment path, exercised

`DISCOVERED -> TRUSTED` is unreachable directly by construction. Walk a node
through the real transitions with the real measurement attached, and assert the
two things `A-042` cares about: an unmeasured node is never routed to, and
re-attestation expiry demotes and **emits**.

### B3 · Reachability, measured not assumed

`MEMORY.md`: **ICMP is blocked both ways on this network. Ping proves nothing.**
TCP/22 is the test. Node 1 hosts the model; this machine does not.

### B4 · The provider adapter — *after* A1 only

One adapter satisfying `Provider.call`, living under `routing/`, keyed by
**profile** and never by product — `INV-HW-1`, and `CI-007` scans exactly that
directory. `routing/` does not exist today, which is why `CI-007` is vacuous;
creating it makes the check live for the first time.

Then the first real completion across the choke point, and the three things that
have only ever been asserted against doubles:

- the cost policy holding on a live call;
- `TRANSIENT` vs `TERMINAL` classification against something that genuinely
  fails — kill the server mid-call and watch the retry timing;
- **exhaustion is not escalation**: revoke every free provider and assert **zero**
  paid attempts at the gateway boundary, which is where `A-004.3` says to count.

### B5 · The home's first producer

The metrics card says `UNAVAILABLE` five times because nothing produces a
reading. With a routed provider there is something to read, and the card stops
being a shape. This is the smallest honest bridge between the two halves of the
project, and it is deliberately last.
