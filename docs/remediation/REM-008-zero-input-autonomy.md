## 1. Problem

**The behavioural requirement exists and is unambiguous. The acceptance layer never tests it.**

Self-initiation is required by RB-005 (*"Do not wait for a user message…"*), DR-005 (*"Continuously evaluate…"*), SR-042, and the prohibition at ARCH-28 (*"Do not reduce autonomy to a cron job that runs isolated scripts"*).

`A-011`, the only autonomy acceptance test, reads in full:

> *"Run a bounded overnight/free-time job using local/free models, checkpointing and resource limits, without waking the user for ordinary work."*

**It is silent on who starts the job.** A human typing *"run the overnight job"* satisfies it completely. ARCH-27's DoD requires *"at least one complete… loop works"* — and `works` ≠ `runs unprompted`. There is no heartbeat, no liveness assertion, and no zero-user-input criterion anywhere in the corpus.

**And the obvious fix is insufficient.** A gate asserting *"≥ N autonomous evaluation cycles with zero user input, ≥1 producing a non-trivial decision"* **is passed by a pure cron build**. Schedule-triggered firing *is* zero-user-input — and scheduled prompting is precisely the thing ARCH-28 excludes. A test that cannot distinguish autonomy from cron does not test the property it exists for.

## 2. The distinction that is actually mechanical

> Genuine autonomy is **not** "acted while no human was present." It is: **the action originated from a state predicate the system evaluated over its own world model, where the predicate's truth was not pre-scheduled.**
>
> A clock may be *an* input. It may not be the *only* input.

This is testable because REM-007 makes `predicate_class` a first-class field: `SCHEDULE | STATE | EVENT | COMPOSITE`. A build whose entire trigger set is `SCHEDULE`-class **fails**, by construction, regardless of how sophisticated it looks.

## 4. Required behaviour — the mechanism

Three architectural properties, each of which must exist in the **production** system, not in test scaffolding.

### 4.1 Liveness — the autonomy loop is observably alive

```
Every evaluation cycle emits autonomy.heartbeat {
    cycle_id, hlc, triggers_evaluated, triggers_fired,
    noops_recorded, operating_period, evaluator_lag_ms
}
```

> **Loop-stopped is an incident with an alert, not a silent condition.** Absence of a heartbeat for `> 3 × tick_interval` raises `autonomy.loop_stalled` and is surfaced to the owner through a path that does not depend on the loop (REM-005's interlock health channel is the natural carrier).

A system whose autonomy loop dies silently is indistinguishable from one that decided there was nothing to do. That ambiguity is exactly what a heartbeat removes.

### 4.2 Provenance — every action resolves to a trigger

Already specified as `INV-TRIG-1` (REM-007). Restated here because the gate depends on it: every autonomous action, **and every recorded no-op**, resolves to exactly one registered `trigger_id` whose predicate demonstrably evaluated true against a **reconstructible world-model snapshot**.

Reconstructibility is what makes this an audit rather than a claim. The snapshot is reconstructible because REM-001 makes world facts HLC-ordered and supersession-preserving: replaying the log to a given HLC yields exactly the state the predicate saw.

### 4.3 The anti-cron discriminator — and the architecture it requires

> **Over the endurance window, at least one action must fire from a trigger whose `predicate_class` is non-`SCHEDULE`** — i.e. it became true because **world-model state changed**, not because a time arrived.

Making this testable imposes a **production architectural requirement**, not merely a test fixture:

> **INV-AUTO-4 — External observation ingress.** The world model MUST be writable by **observation sources that are not part of the decision loop**, through an authenticated ingress that carries provenance, trust class and HLC. The set of such sources is open: physical sensors, node telemetry, external services, and enrolled synthetic observers.

This is not a testing affordance. It is what perception *is*: the world changes, something observes it, the world model updates, and the decision loop reacts to a state it did not schedule. A system whose world model can only be written by its own scheduled activity has no perception, and its "autonomy" is a loop talking to itself. **The fixture in §6 is possible only because this ingress exists in production** — which is the point.

The test harness enrols as a `synthetic_observer` node in trust zone `Z2` (limited trust: may observe, may not hold state or issue commands — REM-011). It uses the same ingress as a camera.

### 4.4 The decision path holds no model capability

Specified as `INV-TRIG-2` and made **observable** by REM-007 §4.4: the evaluator runs in a sandbox with no model capability, and an attempted model call emits `autonomy.model_call_in_decision_path` and raises.

Without observability, "no model call in the decision path" is an assertion about code that a reviewer must believe. With it, the gate detects the violation at runtime, including in a build where the call was added later.

### 4.5 No-op is a first-class outcome

A cycle that fires nothing records `autonomy.noop_recorded` with the `trigger_id` that was closest to firing and the reason it did not. This discharges ARCH-04's *"Silence/no-op is an explicit decision"*, and it is what allows a quiet 24-hour run to be distinguished from a dead one.

## 6. Verification — `A-029`, the three-part gate

**All three parts are mandatory. Passing two is failing.**

**Run configuration:** 24-hour endurance run · **zero user input for the entire window** · `OperatingPeriod = FREE_TIME` throughout · free/local models only (REM-006) · enable token present (REM-005) · full event log retained.

| Part | Assertion | Fails if |
|---|---|---|
| **1 — Liveness** | `autonomy.heartbeat` present at the declared cadence for the whole window, with no gap `> 3 × tick_interval`. `autonomy.loop_stalled` never fires. | The loop dies, stalls, or only runs when poked |
| **2 — Provenance** | **100 %** of autonomous actions resolve to exactly one registered `trigger_id`; each predicate re-evaluates **true** against its reconstructed world-model snapshot. **≥ 1 explicitly recorded no-op carries a `trigger_id`.** | Any action has no trigger, or a snapshot does not reproduce the firing decision |
| **3 — Anti-cron discriminator** | **≥ 1 action fired from a non-`SCHEDULE` `predicate_class`**, where the predicate became true **because externally-injected world state changed**, at a wall-clock time the system could not have anticipated; **and** `autonomy.model_call_in_decision_path` never fired. | **Every trigger that fired is `SCHEDULE`-class** — i.e. the build is cron wearing autonomy's vocabulary |

### 6.1 The discriminator fixture, precisely

```
1. Before the run, an external controller draws a firing time T uniformly at random
   from the 24 h window. T is generated OUTSIDE the system under test, is never
   transmitted to it, and is not derivable from any state it can read.
2. At T, the controller writes an observation through the production external
   observation ingress (§4.3) as an enrolled synthetic_observer in Z2.
       e.g.  world.workshop_space.temperature = 31.4 C
3. A STATE-class trigger registered before the run has predicate
       world.workshop_space.temperature > 30 AND NOT is_unknown(...)
4. ASSERT the trigger fires within <= 2 x tick_interval of T.
5. ASSERT the fired action's trigger_id resolves to that STATE-class trigger.
6. ASSERT the reconstructed snapshot at the firing HLC contains the injected fact.
7. ASSERT autonomy.model_call_in_decision_path did NOT fire during the window.
8. REPEAT with 3 independent draws of T. All three must fire.
```

Steps 1 and 7 together are what a cron build cannot satisfy: it cannot fire on an unanticipated state change, and it cannot substitute a model call for the predicate without emitting the event that fails the gate.

### 6.2 Negative controls — mandatory before the gate is trusted

| Control build | Must produce |
|---|---|
| **C1 — pure cron.** All triggers `SCHEDULE`-class; work fires on a timetable. | **PASSES parts 1 and 2, FAILS part 3.** This run is the evidence that the discriminator discriminates. Without it, `A-029` is unproven. |
| **C2 — model-decides.** The loop asks a model *"is there anything worth doing?"* each cycle. | **FAILS part 3** via `autonomy.model_call_in_decision_path` |
| **C3 — prompt-driven.** The loop runs only when a message arrives. | **FAILS part 1** (no heartbeat between messages) |
| **C4 — silent death.** The loop is killed at hour 6. | **FAILS part 1**, and `autonomy.loop_stalled` fires. Proves a quiet run is distinguishable from a dead one. |

> **C1 is the most important run in the entire verification programme.** It is the only artifact that demonstrates the anti-chatbot property is *tested* rather than *asserted*. It must be executed and its result recorded in the release evidence before `A-029` may be cited.

## 7. Invariants

| ID | Statement |
|---|---|
| **INV-AUTO-1** | The autonomy loop emits a heartbeat every evaluation cycle. Absence beyond `3 × tick_interval` is an incident, not a quiet period. |
| **INV-AUTO-2** | 100 % of autonomous actions and recorded no-ops resolve to exactly one registered `trigger_id` with a reconstructible snapshot. |
| **INV-AUTO-3** | A release may not declare autonomy complete unless `A-029` part 3 passed with a non-`SCHEDULE` trigger and the C1 negative control was recorded as failing part 3. |
| **INV-AUTO-4** | The world model is writable by observation sources external to the decision loop, through an authenticated, provenance-carrying ingress. |
| **INV-AUTO-5** | The trigger registry may not consist exclusively of `SCHEDULE`-class predicates. Registration of a registry with zero non-`SCHEDULE` triggers fails `CI-026`. |

## 8. Failure behaviour

| Failure | Behaviour |
|---|---|
| Loop stalls | `autonomy.loop_stalled`; supervisor restarts the evaluator from checkpoint; incident recorded; **the run's `A-029` evidence is invalidated**, not repaired |
| Heartbeat gap during the endurance run | Run fails part 1. No partial credit. |
| Every fired trigger is `SCHEDULE`-class | Run fails part 3. The build is cron; the finding is recorded as such rather than argued about. |
| External ingress unavailable during the run | Run is **void**, not failed — the fixture could not execute. Re-run required. Distinguishing void from failed matters, because void is a harness defect and failed is a product defect. |
| `autonomy.model_call_in_decision_path` fires once | Run fails part 3 immediately; the call site is a `CI-023` gap and is treated as a defect in the sandbox, not in the trigger |

## 9. Recovery

Not applicable in the usual sense — this is a gate, not a runtime subsystem. Its *failure* recovery is programmatic: a failed `A-029` blocks the autonomy release level, the finding is recorded against the responsible REM, and the run is repeated after correction. **A failed gate is never waived by the implementing engineer** (§5).

## 14. Jarvis-divergence check

> *Could an implementation agent satisfy REM-008 while building an ordinary chatbot?*

**No — this is the single most decisive mechanical test in the programme against the chatbot outcome.** The clause that prevents it: **§6.1 steps 1–4 — the system must act on a world-state change whose timing was drawn outside it and never transmitted to it.** No prompt-driven, scheduled, or request-scoped architecture can produce that behaviour, and the C1 negative control proves the test detects the difference rather than merely asserting it.

The second clause is **`INV-AUTO-4`**: a production ingress that lets the world write into VESPER's model independently of VESPER's own activity. An LLM-plus-memory system has no such surface — its world is whatever was in the last request.
